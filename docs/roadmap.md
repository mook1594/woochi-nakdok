# Roadmap: nakdok

각 Phase는 **종료 조건**을 만족해야 다음으로 넘어간다. 조건을 못 채운 채로
다음 단계를 시작하면 원인 추적이 불가능해진다 — 화자 판별이 틀린 건지 청크
분할이 틀린 건지 섞이는 순간 디버깅이 지옥이 된다.

---

## Phase 0 — 청취 검증 (코드 없음)

**목적**: 한국어 낭독 품질이 장시간 청취에 견디는지 확인. 이게 이 프로젝트의
유일한 진짜 리스크다.

**할 일**
- `pip install supertonic soundfile` — 모델 가중치는 첫 `TTS()` 호출이 자동으로 받는다
- 좋아하는 소설 한 챕터를 그대로 넣어 wav 생성 (분할·정규화·무음 전부 없이)
- M1~M5, F1~F5 10종을 같은 문단으로 돌려 비교
- `speed`(기본 1.05)와 `total_steps`(기본 8)도 같이 흔들어 본다 — 낭독 톤에 직접 영향
- **끝까지 들어본다.** 30초 샘플로는 판단이 안 된다

**판정 기준**
- 20분 연속 청취가 괴롭지 않은가
- 대화문과 내레이션의 톤 차이가 견딜 만한가
- 반복·누락(같은 어절 반복, 문장 뒷부분 증발)이 발생하는가
- 오독이 나온 토큰을 메모 — Phase 2 사전의 시드가 된다

**종료 조건**
- 내레이터로 쓸 보이스 1개를 선택했다
- 오독 토큰 목록을 확보했다

**실패 시**: Kokoro-82M으로 같은 테스트를 반복한다. 둘 다 안 되면 설계를 다시
잡아야 하므로 여기서 멈추고 상의한다.

> 나머지 코드를 한 줄도 쓰기 전에 이 단계를 끝낸다.

---

## Phase 1 — 단일 보이스 파이프라인

**범위**: R1 ~ R7 (LLM 없음, DB 없음, 화자 없음)

**작업 순서**
1. CLI 스캐폴딩 + `.nakdok/` 작업 디렉토리 (R1)
2. 인코딩 감지 + 챕터 분할 (R1, R2)
3. 문장 분할 + 청크 묶기 (R3)
4. 매니페스트 생성 (R4)
5. TTS 합성 + 캐시 (R5, R10.1~10.3)
6. 무음 삽입 (R6)
7. ffmpeg m4b 빌드 (R7)

**종료 조건**
- `nakdok run book.txt`가 재생 가능한 m4b를 만든다
- 오디오북 앱에서 챕터 이동이 동작한다
- `synth`를 두 번 실행하면 두 번째는 TTS 호출 0회
- m4b 총 길이가 매니페스트 `duration_ms` 합계 + 무음 합계와 오차 1초 이내
- **한 권을 실제로 끝까지 들었다**

마지막 항목이 중요하다. 3챕터 샘플로는 안 드러나는 문제(중반부 톤 피로,
장면 전환 처리, 특정 어미의 오독)가 있다.

---

## Phase 2 — 치환 사전과 증분 재생성

**범위**: R8, R10.4

**작업 순서**
1. `lexicon.yaml` 로딩 + 치환 적용 (R8.1~8.3)
2. `text_hash`에 치환 후 텍스트 반영 확인 (R8.2, R10.1)
3. 미등재 토큰 후보 추출 (R8.4)
4. 고아 오디오 파일 보고 (R10.4)

**LLM은 여기서도 쓰지 않는다.** Supertonic은 텍스트 정규화가 내장되어 있고,
Phase 0/1에서 나온 실제 오독 목록을 보면 대부분 고유명사·한자어 수십 개다.
사전 YAML 한 장이 LLM보다 정확하고 빠르다. LLM은 나중에 후보를 뽑는 용도로만
붙인다.

**종료 조건**
- 사전에 항목을 추가하고 `synth`를 돌리면 해당 청크만 재합성된다
- 재합성된 청크 수가 예상과 일치한다 (전수 재합성이 아님)
- 오독이 눈에 띄게 줄었다

---

## Phase 3 — 화자 캐스팅

**범위**: R9, R10 전체

**작업 순서**
1. 세그먼트 분류 — 따옴표 구간 vs 내레이션 (R9.1)
2. 규칙 기반 화자 확정 + 인물 후보 수집 (R9.2, R9.3)
3. `cast.yaml` 생성 + `overrides` 반영 (R9.6, R9.7)
4. **여기서 일단 멈추고 성별 2종 배분만으로 한 권 만들어 듣는다**
5. LLM 화자 판별 (R9.4, R9.5)
6. 통계 리포트 (R9.9)

4번이 중요하다. 규칙만으로 확정되는 비율과 성별 2종 배분의 체감 개선을 먼저
측정해야, LLM 단계에 투자할 가치가 있는지 판단할 수 있다. 여기서 이미 충분하면
5~6번은 안 해도 된다.

**종료 조건**
- 규칙 확정률, LLM 확정률, `unknown` 비율이 숫자로 나온다
- `cast.yaml`의 `overrides`를 고치면 해당 세그먼트만 재합성된다
- `unknown`이 내레이터 보이스로 조용히 폴백된다 (오류로 들리지 않는다)
- 한 권을 캐스팅 적용해서 들었고, 단일 보이스보다 낫다고 판단된다

**주의**: 마지막 조건이 "아니오"일 수 있다. 화자 판별 오류가 잦으면 단일
보이스가 더 편하다. 그 경우 캐스팅을 옵션으로 두고 기본은 끈다.

---

## Phase 4 — 이후 (미확정)

우선순위 없음. 필요해지면 그때 결정한다.

- epub 입력 (챕터 구조가 이미 있어 오히려 쉽다)
- 표현 태그 활용 (`<laugh>`, `<breath>`, `<sigh>`)
- 여러 권 배치 처리 + 잡 큐 + PostgreSQL 메타
- 라이브러리 웹 UI (Blazor)
- 로컬 도서 → 폰 자동 동기화
